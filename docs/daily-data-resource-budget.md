# 个人日频数据仓资源预算

**适用范围：** 全 A 股原始不复权日线、近 8 至 10 年、单人维护、只用于因子研究与回测。

## 基准假设

| 项目 | 预算假设 |
| --- | --- |
| 证券范围 | 约 5,000 至 6,000 个 A 股现役、退市及历史标的；最终以来源证券清单为准 |
| 交易日 | 每年约 240 至 250 个；10 年约 2,450 个交易日 |
| 原始行数 | 约 1,200 万至 1,500 万个 `symbol + trade_date` 日线记录 |
| 原始字段 | 代码、日期、开高低收、成交量、成交额，以及 `source`、`ingested_at`、`data_version`、`adjustment` |
| 存储格式 | 按数据版本和年份分区的 Parquet；DuckDB 仅保存版本、质量和导入元数据 |

上述是容量规划，不是数据覆盖承诺。新股、退市股、停牌日和来源可得性会让实际行数变化。

## 磁盘预算

| 内容 | 保守预留 | 说明 |
| --- | ---: | --- |
| 已发布原始日线 Parquet | 3 至 8 GB | 列式压缩后通常远小于 CSV；实际受代码、日期、浮点精度和分区影响 |
| 导入中的 CSV、临时 Parquet 和校验副本 | 8 至 20 GB | 回填和重试阶段需要保留，不应边导入边删除证据 |
| DuckDB、manifest、运行日志和研究 artifact | 1 至 3 GB | 数据仓元数据较小，报告与图表会逐步增长 |
| 修订版本、日增量和安全余量 | 15 至 30 GB | 保留可回滚版本，避免磁盘接近满载损坏导入 |
| **建议可用空间** | **至少 50 GB，建议 100 GB** | 不含个人其他文件；全量二次基线或更多衍生层需要单独扩容 |

不建议把原始日线全部复制进 SQLite、PostgreSQL 或 DBeaver 管理的单张大表。DBeaver 用于查看 `warehouse.duckdb` 元数据；行情明细由 Parquet 保存和扫描。

## 时间预算

| 阶段 | 单人实际工作量 | 机器运行时间 | 停止条件 |
| --- | --- | --- | --- |
| 两标的一年 CSV 演练 | 1 至 2 小时 | 分钟级 | 质量门禁或固定版本复跑未通过 |
| 字段、复权和许可证复核 | 2 至 4 小时 | 无 | 口径不明确、授权不清楚或无法固定快照 |
| 首次全市场回填 | 2 至 6 小时值守 | 数小时至数天，取决于离线文件或授权接口 | 失败标的超阈值、交易日覆盖缺失或磁盘余量不足 |
| 每日增量更新 | 5 至 15 分钟 | 分钟级 | 非交易日、来源不可用或质量门禁失败 |
| 每周抽样复核 | 20 至 40 分钟 | 分钟级 | 发现供应商修订、异常 OHLC 或血缘缺失 |

首次回填的最大不确定性不是 Parquet 写入速度，而是数据源可得性、限流、字段口径和缺失标的处理。因此优先使用可下载、可哈希的离线快照；在线接口只可作复核或受控补充。

## 批量与成本上限

初始建议设置：

```text
导入批量：每批 50 至 200 个标的
最大重试：2 次
失败标的比例：正式发布为 0；演练也不允许静默跳过
并行任务：1 个
研究任务并发：1 个
```

个人维护的成本上限不是“零费用”，而是可解释、可停止：

- 不购买专业数据前，先完成两标的一年演练，确认数据源的授权和口径。
- 不为短期便利引入云数据库、持续爬虫、代理池或高频数据服务。
- 不把 LLM 调用用于无边界因子裂变；每次任务记录候选数、变形轮数、调用数和回测数。
- 若维护时间连续两周超过每周 2 小时，或来源频繁失效，应暂停扩展范围，评估内部导出或专业数据授权的实际成本。

## 开始全量回填前的检查

- [ ] 本机目标磁盘有至少 50 GB 可用空间。
- [ ] 已确认来源许可证、覆盖范围和原始不复权口径。
- [ ] 两标的一年演练已发布，且固定 `data_version` 复跑成功。
- [ ] 导入失败、质量失败和来源修订都有停止与复盘记录。
- [ ] 不把本项目用于交易、下单或实盘执行。
