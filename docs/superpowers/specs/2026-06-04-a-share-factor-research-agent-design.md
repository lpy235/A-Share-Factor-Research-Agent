# A-Share Factor Research Agent Implementation Design

## 1. Project Goal

Build an A-share factor research agent for quant strategy research workflows.

The system helps complete a simplified but realistic factor research workflow:

1. Find public research materials or read user-provided materials.
2. Extract factor hypotheses from papers, reports, and public articles.
3. Convert factor ideas into a restricted, executable Factor DSL.
4. Fetch A-share daily market data.
5. Compute factors and run validation.
6. Backtest single factors and selected factor combinations.
7. Generate a traceable research report with sources, formulas, metrics, charts, and limitations.

The project is positioned as a research assistant, not an auto-trading system. It should not provide real-money trading advice, order execution, or return promises.

## 2. Target User

Primary user:

- A student preparing for quant strategy, AI + finance, or Agent research and engineering workflows.

Expected demo user:

- A quant researcher or engineer who wants to see whether the project has real strategy research logic, not just a chatbot wrapper.

## 4. Scope

### 4.1 In Scope

Market:

- A-share market only.
- MVP stock universe: CSI 300 or a fixed sample of liquid A-share stocks.
- MVP frequency: daily data.

Research materials:

- Public papers.
- Public PDFs.
- Public broker reports.
- Public finance articles.
- User-provided PDFs.
- User-provided Markdown, text, or notes.

Factor types:

- Momentum.
- Reversal.
- Volatility.
- Volume-price factors.

Validation:

- IC.
- RankIC.
- ICIR.
- Grouped returns.
- Long-short portfolio returns.
- Annualized return.
- Max drawdown.
- Sharpe ratio.
- Turnover.
- Coverage ratio.
- Missing ratio.
- Factor correlation.

Agent capabilities:

- Source discovery.
- Document parsing.
- RAG retrieval.
- Factor hypothesis extraction.
- Factor DSL generation.
- Formula validation.
- Factor execution.
- Backtest execution.
- Factor selection.
- Research report generation.
- Run trace logging.

### 4.2 Out of Scope

The MVP will not support:

- Real-money trading.
- Order execution.
- Stock recommendation.
- Prediction of tomorrow's stock price.
- Minute-level or tick-level high-frequency strategies.
- Paid report scraping.
- Login-required data sources.
- CNKI scraping.
- Wind, Choice, or other paid financial databases.
- Full financial statement factor mining.
- Complex portfolio optimization.
- Arbitrary Python code execution generated by an LLM.

## 5. Source Policy

The system supports two source modes at MVP:

```text
auto: Agent searches public sources.
upload: User provides documents.
```

A later version may support:

```text
hybrid: Use uploaded materials first, then supplement with public materials.
```

Allowed public sources:

- Open public papers.
- Open public PDFs.
- Open finance articles.
- Broker website pages that are publicly accessible.
- Public report pages that do not require login or payment.

Disallowed sources:

- Paywalled reports.
- Login-required broker report platforms.
- CNKI scraping.
- Wind/Choice data scraping.
- Any source that requires bypassing access controls.

Every extracted factor must carry source metadata:

```json
{
  "source_title": "string",
  "source_url": "string | null",
  "source_type": "public_paper | public_report | public_article | user_upload",
  "source_excerpt": "string",
  "page": "number | null"
}
```

## 6. MVP User Flow

### 6.1 Auto Source Mode

Input:

```json
{
  "research_topic": "A股量价类动量因子",
  "source_mode": "auto",
  "universe": "CSI300",
  "start_date": "2020-01-01",
  "end_date": "2025-12-31",
  "max_sources": 5,
  "max_factors": 10
}
```

Flow:

1. Search public sources related to the research topic.
2. Download or read accessible content.
3. Parse documents into chunks.
4. Build a temporary RAG index.
5. Extract candidate factor hypotheses.
6. Convert each hypothesis into Factor DSL.
7. Validate each formula.
8. Fetch A-share daily data.
9. Compute factors.
10. Run factor validation.
11. Run single-factor backtests.
12. Select factors.
13. Build a simple factor combination.
14. Generate a Markdown report.

### 6.2 Upload Source Mode

Input:

```json
{
  "research_topic": "A股动量反转因子",
  "source_mode": "upload",
  "uploaded_files": ["report_001.pdf", "notes.md"],
  "universe": "CSI300",
  "start_date": "2020-01-01",
  "end_date": "2025-12-31",
  "max_factors": 10
}
```

Flow:

1. Parse uploaded documents.
2. Build a local RAG index.
3. Extract candidate factor hypotheses.
4. Continue through DSL, data, validation, backtesting, selection, and reporting.

## 7. Architecture

Recommended architecture:

```text
FastAPI API layer
-> LangGraph agent workflow
-> Source/RAG pipeline
-> Factor DSL generator and validator
-> A-share data service
-> Factor execution engine
-> Backtest and metrics engine
-> Report generator
-> Trace and evaluation layer
```

The LLM should not directly execute arbitrary code. It should only:

- Search and summarize sources.
- Extract hypotheses.
- Generate structured factor DSL.
- Explain results.
- Write reports from verified outputs.

All calculations should be handled by deterministic Python modules.

## 9. Agent Workflow

Use LangGraph to model the workflow as explicit state transitions.

### 9.1 State

```python
class ResearchState(TypedDict):
    run_id: str
    research_topic: str
    source_mode: Literal["auto", "upload", "hybrid"]
    universe: str
    start_date: str
    end_date: str
    sources: list[SourceRecord]
    chunks: list[DocumentChunk]
    retrieved_chunks: list[DocumentChunk]
    factor_hypotheses: list[FactorHypothesis]
    factor_specs: list[FactorSpec]
    validation_results: list[FactorValidationResult]
    backtest_results: list[BacktestResult]
    selected_factors: list[SelectedFactor]
    combined_result: PortfolioResult | None
    warnings: list[str]
    final_report_path: str | None
```

### 9.2 Nodes

Recommended MVP nodes:

```text
PlanResearchNode
CollectSourcesNode
ParseDocumentsNode
BuildRagIndexNode
ExtractHypothesesNode
GenerateFactorDslNode
ValidateFactorDslNode
LoadAshareDataNode
ExecuteFactorsNode
ValidateFactorsNode
BacktestFactorsNode
SelectFactorsNode
GenerateReportNode
```

### 9.3 Node Responsibilities

`PlanResearchNode`

- Normalize the research topic.
- Decide whether to focus on momentum, reversal, volatility, or volume-price factors.
- Produce a short execution plan.

`CollectSourcesNode`

- If `auto`, search public sources and fetch accessible content.
- If `upload`, use user-provided files.
- Enforce source policy.

`ParseDocumentsNode`

- Parse PDF, Markdown, and text.
- Store text chunks with source metadata.

`BuildRagIndexNode`

- Embed chunks.
- Build a vector index for this run.

`ExtractHypothesesNode`

- Retrieve relevant chunks.
- Extract factor hypotheses with source evidence.

`GenerateFactorDslNode`

- Convert hypotheses into restricted Factor DSL.
- Reject vague hypotheses that cannot map to available data fields.

`ValidateFactorDslNode`

- Parse DSL.
- Ensure only allowed operators and fields are used.
- Reject formulas that cannot be executed.

`LoadAshareDataNode`

- Load daily OHLCV data.
- Load optional universe constituents.
- Cache data locally.

`ExecuteFactorsNode`

- Compute factor values using deterministic operators.
- Apply preprocessing.

`ValidateFactorsNode`

- Compute IC, RankIC, ICIR, grouped returns, coverage, missing ratio, and correlations.

`BacktestFactorsNode`

- Run long-short and grouped backtests.
- Compute performance metrics.

`SelectFactorsNode`

- Select stable factors using explicit rules.
- Build equal-weight or IC-weight factor combination.

`GenerateReportNode`

- Generate a Markdown report with tables, charts, sources, formulas, metrics, limitations, and warnings.

## 10. Factor DSL

### 10.1 Why DSL

The LLM must not generate arbitrary executable Python. A restricted Factor DSL gives the project:

- Safety.
- Reproducibility.
- Formula validation.
- Clear design rationale.
- Reduced hallucination risk.

### 10.2 Allowed Fields

MVP fields:

```text
open
high
low
close
volume
amount
```

Optional later fields:

```text
turnover
market_cap
industry
```

### 10.3 Allowed Operators

MVP operators:

```text
returns(x, window)
delay(x, window)
ts_mean(x, window)
ts_std(x, window)
ts_min(x, window)
ts_max(x, window)
rank(x)
zscore(x)
winsorize(x)
neutralize(x, by)
```

Optional later operators:

```text
ts_corr(x, y, window)
ts_rank(x, window)
decay_linear(x, window)
```

### 10.4 Factor Spec Schema

```json
{
  "factor_name": "volume_price_momentum_20",
  "hypothesis": "量价齐升可能代表趋势延续",
  "formula": "rank(returns(close, 20) * ts_mean(volume, 20) / ts_mean(volume, 60))",
  "required_fields": ["close", "volume"],
  "direction": "positive",
  "category": "volume_price_momentum",
  "frequency": "daily",
  "lookback": 60,
  "source_title": "公开研报标题",
  "source_url": "https://example.com/report.pdf",
  "source_excerpt": "过去一段时间成交量放大且价格上涨的股票，可能存在趋势延续效应。",
  "confidence": 0.76
}
```

## 11. Data Layer

### 11.1 MVP Data Provider

Use AKShare first for MVP development because it is easy to start with.

The provider interface should be independent from AKShare:

```python
class AShareDataProvider:
    def get_daily_bars(
        self,
        symbols: list[str],
        start_date: str,
        end_date: str,
    ) -> pd.DataFrame:
        ...

    def get_universe(self, universe_name: str, date: str) -> list[str]:
        ...
```

This keeps the project open to later replacing AKShare with Tushare Pro or another legal data source.

### 11.2 Data Cache

Cache market data locally to avoid repeated downloads.

Recommended MVP cache:

```text
data_cache/
  daily_bars/
  universes/
```

Each cached file should include:

- Provider name.
- Symbols.
- Date range.
- Fetch timestamp.

## 12. Factor Validation

### 12.1 Preprocessing

MVP preprocessing:

```text
replace infinite values
drop rows with missing close
winsorize factor values
zscore factor values cross-sectionally
```

Optional later preprocessing:

```text
industry neutralization
market-cap neutralization
sample in/out split
```

### 12.2 Metrics

For each factor:

```text
mean_ic
mean_rank_ic
icir
coverage_ratio
missing_ratio
turnover
group_return_spread
annualized_return
max_drawdown
sharpe
```

### 12.3 Selection Rules

MVP selection rules:

```text
abs(mean_rank_ic) >= 0.02
abs(icir) >= 0.3
coverage_ratio >= 0.8
missing_ratio <= 0.2
max_drawdown <= configurable threshold
correlation with selected factors <= 0.7
```

The threshold values are intentionally simple and should be configurable.

## 13. Backtest Design

MVP backtest:

- Daily rebalance or weekly rebalance.
- Group stocks by factor quantiles.
- Compute top group, bottom group, and long-short portfolio.
- Include configurable transaction cost.

Default settings:

```json
{
  "rebalance_frequency": "weekly",
  "num_groups": 5,
  "transaction_cost_bps": 10,
  "long_short": true
}
```

The report must show that results are historical backtests and not investment advice.

## 19. Safety and Reliability Rules

The system must:

- Never execute arbitrary LLM-generated Python.
- Only execute whitelisted DSL operators.
- Reject formulas with unknown fields or unknown operators.
- Mark unsupported conclusions as uncertain.
- Include source references for extracted factors.
- Include historical-backtest disclaimer in reports.
- Log rejected sources and rejected formulas.
- Avoid scraping login-required or paid sources.
