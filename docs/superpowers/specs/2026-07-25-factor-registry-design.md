# 因子库第一期设计

## 目标

建立本地、可审计的因子注册表。研究运行中通过选择门禁的因子可以登记为候选；只有人工明确批准后才成为已批准因子。

## 边界

第一期不自动批准因子、不调用交易系统、不修改已有研究运行结果，也不把基金经理 Agent 建议视为最终决策。它只保存可复核的登记和人工决策记录。

## 数据模型

独立 SQLite 数据库保存：

- 不可变因子版本：公式、方向、字段、来源证据、指标、研究运行 ID、数据版本、manifest 哈希和登记时间；
- 追加式决策：`candidate`、`approved`、`rejected`、`retired`，以及决策人、理由和时间。

每次从运行导入时创建新因子版本。公式去重、相似因子聚类和谱系关系留到第二期。

## API

- `POST /factor-registry/from-run/{run_id}`：仅登记运行中的 `selected_factors`，初始为 `candidate`。
- `GET /factor-registry`：返回因子版本、最新状态和数据血缘。
- `POST /factor-registry/{version_id}/decisions`：追加人工决策。

未知运行、未完成运行、无入选因子、缺失规格或非法状态必须被拒绝。因子库不能回写研究流程或触发交易。
