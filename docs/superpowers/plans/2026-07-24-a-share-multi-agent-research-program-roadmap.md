# A 股多智能体投研系统总执行路线

**总目标：** 建设一个面向私募研究场景的日频 A 股因子研究操作系统。系统产出有证据、有版本、有成本假设的因子候选与因子库决策；不发送订单、不连接券商、不承担自动交易职责。

**最终目标形态：** 研究员提交研报、论文、内部材料或研究问题后，系统在固定市场数据版本上完成因子假设、受控裂变、回测验证、样本外检验与成本评估，并形成基金经理式的“拒绝、观察、入库、降级、淘汰”决策记录。

**范围边界：** 本路线覆盖日频数据、因子研究、因子库、多智能体协作和持续监控；不覆盖下单路由、券商接口、自动执行、高频或逐笔基础设施，也不对外提供投资建议。

---

## 一、最终系统结构

```text
研报 / 论文 / 内部研究材料 / 研究问题
                |
                v
分析 Agent：提取证据、经济逻辑与结构化因子假设
                |
                v
研究 Agent：生成 -> 变形 -> 回测 -> 失败归因 -> 再生成
                |
                v
数据与验证 Agent：数据版本、未来函数、成本、OOS、稳定性、相关性
                |
                v
基金经理 Agent：拒绝 / 观察 / 入库 / 降级 / 淘汰
                |
                v
因子库：公式、证据、谱系、实验、决策与监控记录
                |
                v
日常监控：数据质量、因子衰减、相关性拥挤、重新研究触发
```

网页只是研究入口和运营控制台。真正需要长期积累的资产，是原始数据仓、不可变研究实验、因子库记录和决策历史。

## 二、必须遵守的原则

1. **先数据，后智能。** 不能用口径不明、可变或只有复权结果的数据来决定因子是否入库。
2. **先研究，后自动化。** Agent 可以提出、验证和解释，但不参与交易执行。
3. **先证据，后入库。** 每个因子必须能关联到来源材料、证据片段、DSL/代码、数据版本、实验版本和决策理由。
4. **先成本，后收益。** 组合指标必须包含日频交易成本和可交易性约束；不可交易的日期不能被静默忽略。
5. **先样本外，后信心。** 样本内只用于发现；样本外、walk-forward 稳定性、相关性和净成本表现才用于准入。
6. **研究裂变必须有限额。** 每次研究任务都限制 LLM 调用、候选因子数、变形轮数、回测次数和运行时间。
7. **数据源必须可替换。** 团队专业数据、授权供应商、CSV 导出和合规公开数据都应通过统一适配层接入。

## 三、整体阶段与执行顺序

### 阶段 0：研究治理与成本边界

**目的：** 先定义什么是合格因子、系统可消耗多少资源、Agent 可以做什么与不可以做什么。

**交付物：**

- 因子生命周期：`draft`、`candidate`、`under_review`、`observed`、`admitted`、`downgraded`、`retired`。
- 日频研究规范：调仓频率、信号与执行时点、成本口径、股票池、持仓规则和最小历史长度。
- 研究预算：每篇研报最多候选数、最大变形轮数、LLM 最大重试数、并发回测上限。
- 数据来源策略：可使用的内部导出、授权数据、公开数据限制、来源归属和日常更新负责人。
- 因子最低准入标准：固定数据版本、存在来源证据、无未来函数、OOS 与 walk-forward 合格、净成本表现合格、相关性可接受。

**完成标准：** 所有后续 Agent 和因子库都引用同一份研究规则，不能临时修改标准来迎合某个结果。

### 阶段 1：全 A 股日频原始数据底座

**目的：** 建立所有研究结论共同依赖的可信数据底座。

**交付物：**

- 全 A 股近 8-10 年不复权日频 OHLCV、成交额数据。
- 证券主数据、交易日历、上市退市、ST、停复牌、涨跌停状态和公司行为事件表。
- 每一行都有 `source`、`ingested_at`、`data_version`。
- 不可变 Parquet 数据快照、DuckDB 元数据目录、版本 manifest、质量报告和每日增量更新任务。
- 在基础市场数据稳定后，加入历史指数成分股数据。

**完成标准：** 同一 `data_version` 能在数月后复现相同市场数据输入。原始价格保持不复权；任何研究价格转换都必须单独声明转换规则和版本。

**细化计划：** [原始 A 股日频数据仓实施计划](2026-07-24-raw-ashare-daily-data-warehouse.md)。

### 阶段 2：可复现研究与回测引擎

**目的：** 让每一次研究都可解释、可复现，并具备基本经济意义。

**交付物：**

- 非测试模式下，研究任务必须指定已发布的 `data_version`。
- 点时数据访问规则：每个字段记录可得日期，未来数据直接拒绝。
- 日频组合回测：下一交易日执行、佣金、印花税、滑点、换手、停牌、涨跌停、ST、上市天数和历史股票池处理。
- 基准、行业中性、市值中性和暴露诊断，在数据支持后逐步加入。
- IS/OOS、滚动检验、walk-forward、因子衰减、多重检验风险和容量/换手预警。
- 可复现实验产物：数据 manifest 哈希、配置哈希、因子 DSL/代码、报告、指标、图表和事件追踪。

**完成标准：** 任何报告都能回答“使用了哪一版数据、哪一个公式、哪些假设和哪一段代码，才产生这个指标”。

### 阶段 3：版本化因子库

**目的：** 将一次次回测结果沉淀为会累积的研究资产。

**交付物：**

- 因子身份不依赖显示名称，而由规范化 DSL/代码哈希、字段依赖、回看窗口、方向和转换版本共同定义。
- 来源谱系：研报/论文/文档片段、抽取证据、分析说明和原始假设。
- 因子版本及其在不同数据版本、不同实验版本下的研究结果。
- 去重与相似度控制：公式树相似度、因子收益相关性、暴露重叠与经济概念标签。
- 生命周期决策记录：审批人、理由、阈值快照和决策日期。
- 可检索的候选、入库、拒绝和淘汰因子视图。

**完成标准：** 系统再次研究相似因子时，必须明确标记其为已有因子的变体，并比较其相对增益。

### 阶段 4：多 Agent 研究流水线

**目的：** 自动化重复研究工作，但让每个 Agent 有清晰职责、输入输出与停止条件。

| Agent | 输入 | 输出 | 不允许做的事 |
|---|---|---|---|
| 分析 Agent | 研报、论文、内部材料 | 带引用的假设、经济逻辑、字段需求 | 决定因子入库 |
| 研究 Agent | 假设、因子库上下文 | DSL 候选、变形方案、组合方案、失败解释 | 绕过验证或数据版本 |
| 验证 Agent | 因子、数据版本、回测结果 | 未来函数、覆盖率、OOS、稳定性、成本、相关性和偏差结论 | 编造数据 |
| 风险/组合 Agent | 已验证因子 | 组合分散度、换手和风险暴露分析 | 做生命周期决策 |
| 基金经理 Agent | 完整决策包和准入规则 | 拒绝、观察、入库、降级、淘汰建议 | 改写原始指标 |
| 监控 Agent | 入库因子历史与新数据 | 漂移预警和重新研究任务 | 覆盖历史决策 |

**研究闭环：**

```text
提取证据
-> 查询相近因子和历史失败原因
-> 在预算内生成候选
-> 校验 DSL 与数据依赖
-> 在固定数据版本上回测
-> 归因失败类别
-> 仅针对失败原因进行变形
-> 在预算、收敛或出现入库候选时停止
```

**完成标准：** 每一次 Agent 行为都有结构化事件记录；每一个循环都存在候选数、时间和成本上限。

### 阶段 5：基金经理 Agent 决策与因子入库

**目的：** 让因子入库依赖纪律化流程，而不是指标叙事。

**交付物：**

- 策略规则引擎：OOS IC 方向和强度、walk-forward、净成本表现、回撤、换手、容量代理、覆盖率、相关性与数据质量状态。
- 决策包：来源证据、研究谱系、验证报告、相近因子、组合影响和规则命中情况。
- 默认人工复核：基金经理 Agent 提建议，授权研究员确认或覆盖，并记录理由。
- 因子状态切换与定期复验规则。

**完成标准：** 每个入库因子都有完整决策包，并且可以按当时生效的准入规则回溯验证。

### 阶段 6：日常监控与研究反馈

**目的：** 持续维护因子库，但不把监控误做成交易系统。

**交付物：**

- 每日数据质量检查，先于研究和因子刷新。
- 因子健康检查：覆盖率、IC 漂移、换手、相关性拥挤、缺失数据增加和市场状态预警。
- 在新发布数据版本上定期重新验证。
- 触发队列：`data_issue`、`factor_decay`、`correlation_crowding`、`source_update`、`manual_review`。
- 监控页面：展示当前因子库状态、近期异常和决策历史。

**完成标准：** 因子可以基于证据被降级或淘汰，但历史研究和决策记录永久保留。

### 阶段 7：专业数据接入与团队协作

**目的：** 在未来获得团队数据权限后提升数据质量，而无需推倒重建。

**交付物：**

- 团队 CSV/API 的统一适配器。
- 数据源字段映射和质量规则配置。
- 来源凭据、数据权限和研究产物的访问边界。
- 专业/内部数据与基础数据之间的覆盖率、差异和谱系对比。
- 因子、研究任务和决策包的协作评审与负责人机制。

**完成标准：** 新数据源通过同一个数据目录生成新版本，并可以重放同一研究工作流。

## 四、个人执行策略：先做什么，后做什么

### 必须优先完成

- 阶段 0 与阶段 1。
- 在全市场历史回填前，先完成两只股票、一年数据的完整演练。
- 在扩大 Agent 裂变前，先建立因子库数据结构。
- 因子入库默认保留人工确认。

### 暂时不要做

- LLM 微调、自建大规模向量库、无边界的自主变形树、云端复杂部署和大型组合优化。
- 原始市场数据未稳定前的点时财务数据、另类数据和分钟级数据。
- 任何券商、订单、交易或执行接口。

### 价格与时间控制

- 优先使用本地 Parquet + DuckDB，不在单人阶段过早引入云数据库。
- 按文档哈希缓存 LLM 抽取结果，常规结构化解析优先使用规则。
- 在调用 LLM 和全市场回测前先进行低成本数据质量检查。
- 每个研究任务都限制候选数、变形轮数、运行时间和 API 调用次数。
- 从第一天就分离数据源适配层；未来接入团队专业数据只需替换采集层与授权配置。

## 五、什么状态算“项目完成到可用”

满足以下条件，才可以认为系统已具备日频因子研究能力：

1. 已发布的全 A 股日频数据版本可以复现，也可以每日增量更新。
2. 研报可以在不填写主题的情况下直接分析，且证据被保存。
3. 生成因子无法绕过 DSL、未来函数、数据版本、成本、OOS 和稳定性控制。
4. 每个候选和入库因子都有版本化谱系、可比较指标和生命周期决策。
5. 日常监控能够发现数据失败和因子衰减，并触发复核或重新研究。
6. 系统不包含下单、订单路由或自动交易能力。

## 六、现在最先并行推进的三条主线

1. **研究治理文档：** 固化日频准入规则、成本假设和研究预算。
2. **数据仓基础：** 执行原始数据子计划，先发布一个小规模演练版本。
3. **因子库模型：** 在大规模 Agent 生成之前，定义因子身份、谱系、版本、决策和监控记录。

在这三条主线通过各自验收标准前，不启动大规模“7x24 多 Agent 裂变”。
