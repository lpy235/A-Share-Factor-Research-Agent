## 任务 1-3：因子库基础

因子库不是简单地保存因子名称。每个版本必须保存 DSL 公式、字段、方向、原始证据、指标、研究 `run_id`、数据 `data_version` 和 manifest 哈希。只有人工批准记录存在时状态才是 `approved`；候选状态不代表可用因子。

工作台可以从当前或历史研究运行登记已选因子，并在页面内追加人工决策。基金经理 Agent 的建议会单独记录，不能更改因子库状态。

## 任务 4-6：多 Agent 研究闭环

变形引擎不能任意生成 Python 或无限调用 LLM。它只能在受限 DSL 和任务预算内工作。研究 Agent 只负责实验和淘汰，基金经理 Agent 只负责建议；二者都不能绕过人工审批或固定数据版本。

实验 API 仅接受使用 `warehouse` 且绑定已发布 `data_version` 的已完成研究运行。实验记录候选上限、变形轮数、回测上限、零 LLM 调用、父因子与每个淘汰原因。

## 任务 7-9：可信数据底座

真实日频数据在系统中优先级高于研究结果。任务 8 与任务 9 必须使用可授权、可复核的本地快照，不能用 adata、AKShare 或 fixture 伪装为正式历史库。任务 8 是全市场回填前唯一必要演练。

发布前质量检查现覆盖证券主表、交易日历、证券状态和公司行为契约；一旦提供，格式或主从一致性错误会阻止发布。正式全市场导入必须启用 `--formal-baseline --provenance-json <file>`，该模式自动要求四类参考表，并验证来源、授权/许可、覆盖范围、不复权声明和人工复核的本地元数据契约；任一缺失均阻止发布并保留草稿。元数据只证明操作者提供了证据，不能替代人工核验来源许可。未启用正式模式时，缺失参考表仅保留警示，以兼容当前受控 bars-only CSV 演练入口。

本地两标的一年演练记录见 [验收记录](market-data-two-symbol-rehearsal.md)。该快照仅验证流程和版本复现，不能替代任务 9 所需的正式全市场离线基线。

## 任务 10：验收标准

从一份上传研报开始，系统应能产生可解释因子候选、记录变形谱系、使用一个已发布的数据版本回测、展示 OOS 与稳定性门禁、给出基金经理 Agent 建议，并由人工在因子库中留下最终决定。整个链条无需交易账户、券商连接或下单模块。
